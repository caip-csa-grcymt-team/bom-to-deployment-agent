## Scope

This instruction file defines the Azure resource naming convention for all resources generated by the `infra-provisioner` agent. Apply these rules when setting the `name` parameter on every AVM module invocation in `main.bicep`.

## Base Pattern

```text
<prefix>-<appname>-<env>-<region>-<number>
```

Example: `kv-min69rg170-dev-weu-01`

## Variable Definitions

### prefix

The Cloud Adoption Framework (CAF) resource abbreviation. See the full prefix reference table below.

Reference: <https://learn.microsoft.com/en-us/azure/cloud-adoption-framework/ready/azure-best-practices/resource-abbreviations>

### appname

Derived from the infra-planner tags: `{authority}-{project}` converted to lowercase with dashes removed for constrained resources.

For a BOM with Authority ID `MIN69` and Project ID `RG170`, the appname is `min69rg170`.

### env

Environment code passed as a pipeline parameter:

| Environment | Code |
|---|---|
| Development | `dev` |
| Staging | `stg` |
| Production | `prd` |

### region

Azure region abbreviation:

| Azure Region | Code |
|---|---|
| `westeurope` | `weu` |
| `swedencentral` | `swe` |
| `northeurope` | `neu` |
| `eastus` | `eus` |
| `eastus2` | `eus2` |
| `westus` | `wus` |
| `centralus` | `cus` |
| `uksouth` | `uks` |
| `ukwest` | `ukw` |
| `germanywestcentral` | `gwc` |

### number

Zero-padded two-digit sequence starting at `01`. Increment for multiple instances of the same resource type (e.g., `01`, `02`, `03`).

## Resource-Specific Overrides

Some Azure resources impose naming constraints that override the base pattern.

### Storage Account

Pattern: `st{appname}{env}{region}{number}`

Constraints: lowercase alphanumeric only, no dashes, 3-24 characters.

```bicep
// Example: stmin69rg170devweu01
var storageAccountName = take(toLower(replace('st${applicationName}${environment}${region}01', '-', '')), 24)
```

### Key Vault

Pattern: `kv-{appname}-{env}-{region}-{number}`

Constraints: 3-24 characters, alphanumeric and dashes.

If the full name exceeds 24 characters, truncate `appname` to fit.

```bicep
// Example: kv-min69rg170-dev-weu-01
var keyVaultName = take('kv-${applicationName}-${environment}-${region}-01', 24)
```

### Container Registry

Pattern: `cr{appname}{env}{region}{number}`

Constraints: lowercase alphanumeric only, no dashes, 5-50 characters.

```bicep
// Example: crmin69rg170devweu01
var acrName = toLower(replace('cr${applicationName}${environment}${region}01', '-', ''))
```

### SQL Server

Pattern: `sql-{appname}-{env}-{region}-{number}`

Constraints: lowercase, 1-63 characters, dashes allowed but not at start or end.

### Cosmos DB

Pattern: `cosno-{appname}-{env}-{region}-{number}` (NoSQL) or `cosmon-{appname}-{env}-{region}-{number}` (MongoDB)

Constraints: lowercase, 3-44 characters.

### Virtual Machine

Pattern: `vm-{appname}-{env}-{number}`

Constraints:

- **Windows VMs**: The `computerName` (OS hostname) must be **no more than 15 characters**. Because the resource name and computer name are typically kept in sync, limit the full VM name to 15 characters for Windows VMs. Truncate `appname` aggressively or omit `env`/`region` segments to fit.
- **Linux VMs**: 1-64 characters.

> **⚠️ Windows VM Naming Hint**: A name like `vm-min69rg170-dev-01` is 21 characters and will **fail** deployment for Windows VMs. Shorten to fit within 15 characters (e.g., `vm-min69rg-d-01`).

```bicep
// Windows VM — must be ≤ 15 characters
// Example: vm-min69rg-d-01 (15 chars)
var windowsVmName = take('vm-${take(applicationName, 6)}-${take(environment, 1)}-01', 15)

// Linux VM — up to 64 characters, standard pattern applies
// Example: vm-min69rg170-dev-01
var linuxVmName = 'vm-${applicationName}-${environment}-01'
```

## Subnet Naming

Pattern: `snet-{purpose}-{appname}-{env}-{region}-{number}`

The `purpose` segment indicates the subnet's function:

| Purpose | Description |
|---|---|
| `pe` | Private Endpoints |
| `app` | App Service VNet integration |
| `aks` | AKS node pools |
| `cae` | Container App Environment |
| `mysql` | MySQL Flexible Server delegation |
| `psql` | PostgreSQL Flexible Server delegation |
| `agw` | Application Gateway |
| `bas` | Azure Bastion (`AzureBastionSubnet` required name) |
| `fw` | Azure Firewall (`AzureFirewallSubnet` required name) |
| `gw` | VPN/ExpressRoute Gateway (`GatewaySubnet` required name) |
| `vm` | Virtual Machines |

Azure requires specific names for certain subnets. Override the pattern for these:

| Subnet Purpose | Required Name |
|---|---|
| Azure Bastion | `AzureBastionSubnet` |
| Azure Firewall | `AzureFirewallSubnet` |
| VPN/ER Gateway | `GatewaySubnet` |

## Private DNS Zone Naming

Private DNS Zones use Azure-standard names exactly. Never customize or abbreviate DNS zone names:

```bicep
// Correct
name: 'privatelink.blob.core.windows.net'

// Incorrect — never do this
name: 'pdnsz-blob-${applicationName}'
```
